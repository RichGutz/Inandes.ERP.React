# 05. Módulo Originación - Análisis y Plan (Migración a React)

**Fecha de Análisis:** 16 de Julio, 2026
**Objetivo:** Migrar el script legacy `02_Originacion.py` (Streamlit) hacia el ecosistema React, manteniendo una correspondencia funcional del 100% pero aplicando una UI/UX moderna, tipo "Landing/App" corporativa con React y Tailwind.

---

## 1. Entendimiento del Módulo Original (Legacy)

El módulo de Originación es el core operativo de factoring. Permite procesar lotes de facturas, simular tasas, generar reportes (PDFs) y formalizar la operación subiendo todo a Google Drive y registrando en Base de Datos (Supabase).

Se divide en 6 secciones funcionales principales:

### 1. Carga de Facturas (Buckets / Grupos)
- Permite configurar de 1 a 8 "grupos" o "buckets".
- Cada grupo tiene su propio `uploader` para PDFs de facturas.
- Al procesar el lote, se extrae el texto del PDF y se hace un parseo para obtener metadatos (RUC, Empresa, Montos, Moneda, Fecha de Emisión).
- **Lógica DB:** Se busca el RUC del emisor en la BD para autocompletar la Razón Social y sus condiciones financieras pre-aprobadas (tasas, días mínimos, comisiones).

### 2. Configuración Global
- Un panel para aplicar parámetros masivos a todo el lote de facturas cargadas:
  - Comisión de Estructuración (% y Mínimos PEN/USD)
  - Comisión de Afiliación (PEN/USD)
  - Fechas Globales (Desembolso) y Días de interés mínimo.
  - Tasas Globales (Avance, Mensual, Moratorio).

### 3. Detalle y Edición de Facturas
- Lista de todas las facturas parseadas (agrupadas por Bucket).
- Permite edición manual de cualquier metadato o tasa extraída.
- **Perfil de Operación (Preview):** Un desglose en tabla mostrando: Monto Neto, Tasa de Avance, Margen, Capital, Intereses, Comisiones, IGV, y el Monto a Desembolsar final.

### 4. Simulación, PDFs y Formalización
- **Calcular Facturas:** Llama a dos algoritmos core (`procesar_lote_desembolso_inicial` y `procesar_lote_encontrar_tasa`) para el cuadre matemático exacto (Goal Seek para el redondeo a 10).
- **Drive Picker:** Un navegador que permite al usuario buscar y seleccionar una carpeta destino en Google Drive.
  - **Auto-parseo:** Extrae inteligentemente el "Número de Contrato" y "Número de Anexo" a partir del nombre de las carpetas seleccionadas (ej. `Contrato_2025_Enero/Anexo_1`).
- **Generación de PDFs:** 
  - Genera el *Perfil de la Operación* y el *Anexo de Liquidación* usando data del lote y cuenta bancaria obtenida de la BD.
- **Guardar y Subir Todo (Upload Paralelo):** 
  - Sube todos los PDFs originales y los generados (Perfil + Anexo) a Google Drive de forma paralela (hasta 5 hilos).
  - Actualiza Supabase con la propuesta operativa y hace *tracking* del estado.

### 5 y 6. Integración CAVALI (XML y Letras)
- Generación y descarga de archivos específicos para subir a la plataforma CAVALI.

## 2. Estrategia de Migración a React

La lógica de negocio pesada (Parseo de PDFs, PDF generation, Google Drive upload, Algoritmos Financieros) **NO se traducirá a TypeScript** en el Frontend.
Debido a que React/Vite corren en el navegador del cliente:
1. No podemos usar `pdfplumber` ni leer archivos nativos pesados con Python.
2. No podemos/debemos manejar credenciales Service Account de Google Drive directamente en el Frontend.
3. No podemos usar librerías de generación PDF Python nativas ni `concurrent.futures`.

### 2.1. Arquitectura API-First (Backend for Frontend)
El frontend de React será estrictamente **Presentacional + Manejo de Estado**, y se apoyará en una nueva API (FastAPI) para las tareas pesadas.

#### Rutas API requeridas a desarrollar/exponer en el Backend:
- `POST /api/originacion/parse-invoices`: Recibe `multipart/form-data` con los PDFs y devuelve un JSON con la data parseada (`emisor_ruc`, montos, etc).
- `POST /api/originacion/calculate-batch`: Recibe el JSON del lote de facturas y devuelve el cálculo final (Goal Seek, Intereses, Desglose).
- `GET /api/drive/list-folders`: Para reemplazar el "Drive Picker" local, devolviendo el árbol de directorios de Google Drive.
- `POST /api/originacion/generate-pdfs`: Genera los PDF en Python y devuelve un base64 o link de descarga efímero.
- `POST /api/originacion/formalize-batch`: Sube todos los PDFs al Drive destino y guarda en Base de Datos de un solo golpe.

### 2.2. Diseño de Componentes (React UI)

El flujo en React se dividirá en un "Stepper" o pestañas secuenciales para no saturar al usuario:
1. **Step 1: Upload (Drag & Drop)** - Reemplaza los 8 buckets por zonas dropzone dinámicas.
2. **Step 2: Revisión y Configuración** - Tabla/Grid de edición masiva y panel lateral de parámetros globales.
3. **Step 3: Simulación y Resultados** - Acordeones por factura mostrando el "Perfil de la Operación".
4. **Step 4: Formalización** - Selección de carpeta (Drive Picker Custom Component) y Generación de Contratos.

## 4. Lineamientos Críticos para los Siguientes Agentes (Módulos Restantes)

Si vas a tomar el relevo para construir los siguientes módulos del menú (Aprobaciones, Desembolsos, Liquidaciones, Repositorio, Dashboard), es imperativo que acates las siguientes **Líneas Rojas** establecidas tras el refactor de Originación:

### A. Regla de UI/UX: Cero Inventos, Flujo Continuo
- **Prohibido usar Steppers o Múltiples Tabs internas:** El usuario exige que la disposición (layout) sea **copia fiel de Streamlit**.
- Streamlit renderizaba toda la aplicación top-to-bottom en una sola pantalla (Scrolling continuo). La adaptación a React debe respetar este mismo flujo vertical progresivo.
- "Diferente cara" significa usar Tailwind CSS para embellecer los botones, tablas y formularios, **NO** significa reestructurar la UX del módulo.
- **Acción:** Abre el script original de Streamlit (ej. `04_Liquidaciones.py`) y mapea sus secciones literalmente de arriba hacia abajo en el componente de React.

### B. Regla Backend: Desacoplamiento Físico Total
- **Prohibido acoplarse al monolito legacy:** Ya no vivimos en `mini_erp_v2_antigravity`.
- **Acción:** Toda lógica en Python requerida por un módulo (routers, utilitarios, integraciones) debe ser **copiada físicamente** a la carpeta nativa `C:\Users\rguti\Inandes.ERP.React\backend\`. 
- **Prohibido usar `sys.path.insert`:** El código Python debe adaptarse limpiamente para que sus imports nazcan desde la nueva carpeta `backend/` sin buscar dependencias externas.

- Debes reconstruirlos desde cero, leyendo el script de Streamlit respectivo y traduciendo su layout top-to-bottom a JSX/Tailwind.

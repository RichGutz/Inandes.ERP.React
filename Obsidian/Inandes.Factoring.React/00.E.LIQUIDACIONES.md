# 00.E - Módulo de Liquidaciones

## 1. Principio Fundamental (Legacy First)
El módulo de Liquidaciones en React **NO DEBE** reinventar la rueda matemática. Todo el motor de cálculo ("Master Audit", "Oracle Evaluator", cálculo de intereses mínimos, moras, IGVs y pagos parciales) ya existe y está blindado en el backend de Python (`mini_erp_v2_antigravity/testing_audit_liquidation/tabla_maestra_auditoria.py` y `core.liquidation_calculator`).

El trabajo de React es puramente **UI/UX**, orquestando la comunicación con los endpoints de FastAPI y mostrando las tablas de resultados.

## 2. Flujo Funcional (Basado en 05_Liquidacion.py)

El submódulo se divide en dos grandes vistas (Pestañas/Tabs):
1. **Liquidaciones Nuevas:** Facturas que actualmente están en estado `DESEMBOLSADA`. Reciben su primer pago del cliente/aceptante.
2. **Liquidaciones en Proceso:** Facturas en estado `EN PROCESO DE LIQUIDACION` (recibieron un pago parcial previo pero aún tienen capital remanente).

Para ambas vistas, el flujo de usuario es:
- **Seleccionar Factura(s):** Búsqueda y selección de la factura a liquidar.
- **Ingresar Datos de Pago:**
  - Fecha Real de Pago.
  - Monto Recibido (Abonado en la cuenta de InAndes).
- **Simular Liquidación (Botón "Calcular/Previsualizar"):** 
  - Llama al backend pasándole la fecha y monto.
  - El backend devuelve la `tabla_maestra_auditoria` (día a día) y el Resumen de G&P Operativo.
  - React dibuja estas dos tablas visualmente (idénticas al legacy).
- **Formalización (Registro):**
  - Subir el Voucher de depósito del cliente (PDF/IMG).
  - Selección de carpeta destino en Drive.
  - Llama a `POST /api/liquidaciones/procesar_liquidacion_lote`.
  - El backend evalúa si el pago cubre todo (Estado: `LIQUIDADA`) o solo una parte (Estado: `EN PROCESO DE LIQUIDACION`) y sube el archivo a Drive.

## 3. Consideraciones Críticas (Backend / Frontend)

- **Backend Ready:** El router `liquidaciones.py` ya existe en el backend, pero debe ser revisado para asegurar que expone los endpoints necesarios (`GET pendientes`, `POST simular_liquidacion`, `POST procesar_liquidacion_lote`).
- **UI de Simulación:** La tabla "Detalle Diario" y el cuadro de "Liquidación Financiera - G&P Operativo" son sagrados. Deben mostrarse con total claridad:
  - Base de Cálculo
  - Capital Remanente
  - Int. Devengado, Mora, IGV, Comisiones.
  - Saldo a favor o en contra del cliente.
- **Pagos Parciales:** La lógica del "Candado del Primer Pago" (cobrar mínimo 15 días o comisiones primero) la maneja el backend. React solo debe enviar el `monto` y `is_first_payment`, y renderizar lo que devuelva el backend.

## 4. Estructura UI (React)
- Componente Principal: `LiquidacionesTab.tsx`
- Subcomponentes (sugeridos):
  - `LiquidacionSimulador.tsx`: Renderiza las tablas de G&P y Detalle Diario.
  - `LiquidacionFormalizador.tsx`: Uploader del voucher de pago y selector de Drive.

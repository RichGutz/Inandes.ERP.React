# Módulo de Aprobación (React)

## Propósito
El módulo de Aprobación es el tercer paso en el flujo de Factoring. Recibe las propuestas de operaciones que fueron "Originadas" exitosamente (estado `ACTIVO` en la tabla `propuestas`) y permite a un usuario revisarlas y cambiar su estado a `APROBADO`.

## Flujo de Trabajo
1. **Carga de Datos:** El frontend llama al endpoint `GET /api/aprobacion/pendientes`. El backend (`supabase_repository.get_active_proposals_for_approval()`) retorna todas las facturas en estado `ACTIVO`.
2. **Mock de Estados Externos:** Como los sistemas Cavali e ICL (Letras) no están integrados directamente, el sistema simula (mock) aleatoriamente si la factura fue `ACEPTADA` o si la letra está `FIRMADA`.
3. **Agrupación y Navegación UI:**
   - La interfaz agrupa las facturas por la **primera letra** de la empresa (Emisor). Muestra botones `A-Z` interactivos con contadores de facturas pendientes.
   - Al seleccionar una letra, se muestran "Acordeones" anidados: `Empresa > Lote > Grupo`.
   - Dentro del Grupo, se encuentra una tabla con las facturas individuales.
4. **Validación:**
   - Para aprobar, la factura idealmente debe tener estado Cavali `ACEPTADA` y Letra `FIRMADA`.
   - Si no cumple, el sistema arroja una alerta. Sin embargo, el usuario puede seleccionar la casilla "Aprobación forzada" para ignorar esta validación temporalmente.
5. **Confirmación:**
   - Al dar clic en "Aprobar Operaciones", el frontend envía una lista de `proposal_ids` a `POST /api/aprobacion/aprobar`.
   - El backend cambia el estado de cada una a `APROBADO` usando `update_proposal_status()`.
6. **Notificación (Mock):** Tras el éxito, se muestra en pantalla un bloque de texto formateado listo para ser copiado o enviado por correo al área de desembolsos.

## Endpoints (FastAPI - `routers/aprobacion.py`)
- `GET /api/aprobacion/pendientes`: Retorna la data cruda desde Supabase de facturas `ACTIVO`.
- `POST /api/aprobacion/aprobar`: Actualiza múltiples IDs a `APROBADO`. Registra eventos en la tabla `audit_log`.

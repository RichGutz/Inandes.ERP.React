## 🔍 2. Mecanismo de Extracción y Búsqueda de Involucrados (Emisor y Aceptante)

El backend de Python (`pdf_parser.py` y `supabase_repository.py`) obtiene y valida los datos de los involucrados (Emisor y Aceptante) mediante un proceso de dos fases:

```
[ PDF de Factura ]
       │
       ▼ (1. Parseo mediante pdfplumber y RegEx)
       ├─► all_rucs[0]  ──► emisor_ruc  (Proveedor / Cedente)
       └─► all_rucs[1]  ──► aceptante_ruc (Cliente / Adquirente)
       │
       ▼ (2. Consulta a Supabase: Tabla "EMISORES.ACEPTANTES")
       ├─► get_razon_social_by_ruc(emisor_ruc)    ──► Razón Social Oficial del Emisor
       ├─► get_razon_social_by_ruc(aceptante_ruc) ──► Razón Social Oficial del Aceptante
       └─► get_financial_conditions(emisor_ruc)  ──► Precarga de Tasas Comerciales
```

### **Fase 1: Extracción de RUCs desde el PDF (`pdf_parser.py`)**
1. El archivo PDF se lee con `pdfplumber` y se convierte a texto plano normalizado.
2. Se ejecuta una expresión regular (RegEx) para capturar todos los RUCs válidos de Perú (11 dígitos comenzando en `20` o `10`):
   $$\text{RegEx: } \texttt{\textbackslash b(20\textbackslash d\{9\}|10\textbackslash d\{9\})\textbackslash b}$$
3. **Mapeo por posición tributaria:**
   - **`all_rucs[0]` (1er RUC encontrado):** Se asigna como **`emisor_ruc`** (el emisor de la factura / cliente cedente).
   - **`all_rucs[1]` (2do RUC encontrado):** Se asigna como **`aceptante_ruc`** (el aceptante o deudor de la factura).

### **Fase 2: Enriquecimiento y Búsqueda en Supabase (`supabase_repository.py`)**
Con los RUCs extraídos, el backend ejecuta consultas a Supabase sobre la tabla **`EMISORES.ACEPTANTES`**:

```python
# Consulta de Razón Social Oficial
emisor_nombre = db.get_razon_social_by_ruc(emisor_ruc)
aceptante_nombre = db.get_razon_social_by_ruc(aceptante_ruc)

# Consulta de Condiciones Comerciales del Cliente
db_rates = db.get_financial_conditions(emisor_ruc)
```

1. **Razón Social Oficial:** Si el RUC ya existe en Supabase, la Razón Social registrada sustituye o completa la lectura del PDF, corrigiendo erratas o faltas de ortografía del escaneo.
2. **Autocompletado de Tasas Comerciales:** Para el `emisor_ruc`, se leen las condiciones comerciales pactadas y registradas en la BD:
   - `tasa_avance` (por defecto 90% a 98%)
   - `interes_mensual_pen` / `interes_mensual_usd` (por defecto 2.5%)
   - `interes_moratorio_pen` / `interes_moratorio_usd`
   - `dias_minimos_interes` (por defecto 15 días)
   - `comision_estructuracion_pct` y montos mínimos (`min_pen`, `min_usd`).

## 🧮 5. Algoritmo y Fórmulas del Motor Financiero

Para cada factura $i$, el motor en Python (`factoring_calculator.py`) ejecuta:

1. **Cálculo del Plazo Operativo:**
   $$\text{Plazo Factura } i = \max\Big( (\text{Fecha Pago}_i - \text{Fecha Desembolso}_i)_{\text{días}}, \, \text{Días Mínimos}_i \Big)$$

2. **Cálculo de Tasa Diaria e Interés Ganado:**
   $$\text{Tasa Diaria} = (1 + \text{Interés Mensual}_i)^{1/30} - 1$$
   $$\text{Capital Avance} = \text{Monto Neto}_i \times \text{Tasa Avance}_i$$
   $$\text{Interés Ganado} = \text{Capital Avance} \times \Big( (1 + \text{Tasa Diaria})^{\text{Plazo Factura } i} - 1 \Big)$$
   $$\text{IGV Interés} = \text{Interés Ganado} \times 0.18$$

3. **Cálculo del Abono Real Líquido a Cedente:**
   $$\text{Comisión Estructuración} = \max\Big( \text{Monto Neto}_i \times \text{Estructuración \%}, \, \text{Mínimo Moneda} \Big)$$
   $$\text{Abono Real Líquido} = \text{Capital Avance} - (\text{Interés Ganado} + \text{IGV Interés}) - (\text{Comisión Estructuración} + \text{IGV Comisión})$$

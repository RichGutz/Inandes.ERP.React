# Procedimientos de Despliegue y Base de Datos

Esta nota sirve como referencia permanente para los Agentes IA (y humanos) sobre cómo operar, desplegar y conectar los servicios del ecosistema ERP Factoring INANDES.

## 1. Procedimiento de Lanzamiento en Entorno Local (Desarrollo)

Para probar la integración completa entre la Interfaz y el Backend, debes tener dos terminales (Powershell) independientes:

**A. Backend (FastAPI - Python)**
- Directorio: `C:\Users\rguti\Inandes.ERP.React\backend`
- Comando: `uvicorn main:app --reload`
- *Nota: Levanta el puerto 8000 por defecto. Aquí conviven las APIs de CRM y Factoring (Originación).*

**B. Frontend (React - Vite)**
- Directorio: `C:\Users\rguti\Inandes.ERP.React`
- Comando: `npm run dev`
- *Nota: Levanta en el puerto local (usualmente 5173). Es el cliente que consume los servicios de Supabase y el Backend FastAPI.*

> **REGLA CRÍTICA PARA AGENTES:** Los agentes NO DEBEN ejecutar `uvicorn` ni `npm run dev / streamlit run` directamente mediante tools, ya que son procesos síncronos continuos que bloquean la sesión de Gemini. El usuario debe lanzarlos manualmente en su propio Powershell.

## 2. Conexión con Supabase (SSL Obligatorio)

Toda conexión hacia la base de datos de PostgreSQL administrada por Supabase, ya sea desde Python (SQLAlchemy / psycopg2) o cualquier otro cliente directo de BD, **debe requerir SSL obligatoriamente**.

**Cadena de Conexión en Backend (Python):**
Asegurarse de que el String termine en `sslmode=require`:
```ini
postgresql://postgres.[PROYECTO]:[PASSWORD]@aws-0-us-west-1.pooler.supabase.com:6543/postgres?sslmode=require
```

**Conexión en Frontend (React):**
El SDK de Javascript gestiona el SSL automáticamente por debajo usando HTTPS:
```javascript
import { createClient } from '@supabase/supabase-js';
export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY
);
```

## 3. Procedimiento de Despliegue (VPS / Producción)

El proceso oficial de despliegue al entorno de producción (o VPS asociado vía Railway) sigue una estrategia de Git y Webhooks.

**Despliegue de React y Backend:**
- Agregar cambios: `git add .`
- Hacer commit: `git commit -m "Descripción concisa"`
- Empujar al remoto asociado al pipeline: `git push railway main`

El servicio de nube capturará el push, reconstruirá la imagen (o el `npm run build` en caso de React) y aprovisionará el nuevo entorno automáticamente.

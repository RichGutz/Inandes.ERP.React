# 🏢 Estructura General del ERP InAndes

Bienvenido a la documentación de arquitectura del **Mini ERP & CRM InAndes** (versión consolidada a 2026). Este sistema ha sido desarrollado originalmente en **Streamlit** y está siendo analizado para su migración definitiva a **React + Vite**.

El sistema se compone de tres capas principales:
*   **Frontend**: Interfaz interactiva y tabulada (originalmente en Streamlit con menús de acceso restringido).
*   **Backend & Lógica Financiera**: Motores de cálculo en Python (cálculo diario de rendimiento, comisiones y balances con base 360). Ver detalle en [[Backend/Entendimiento del Backend y Logica Financiera]].
*   **Base de Datos**: Base de datos relacional PostgreSQL alojada en Supabase que funciona como ledger de transacciones y estados. Ver detalle en [[Database/Entendimiento de la Base de Datos]].

## 🗂️ Mapeo y Descripción de Módulos (Streamlit)

A continuación se detallan los módulos activos organizados por su área de responsabilidad dentro de la empresa.

### 1. ⚙️ Core de Factoring y Confirming (Operaciones)
Módulos dedicados al negocio tradicional de compra y cobro de facturas comerciales:

*   **`00_Dashboard.py`**: Panel de control general. Presenta métricas operativas de factoring, AUM (Assets Under Management) consolidado de fondos y resumen visual de riesgos.
*   **`01_Registro.py`**: Interfaz de registro para empresas clientes, proveedores, y cargamento masivo de datos iniciales.
*   **`02_Originacion.py`**: Módulo robusto para el proceso de originación de operaciones financieras. Maneja la carga de archivos, análisis de facturas y cesión electrónica.
*   **`03_Aprobacion.py`**: Flujo de aprobación donde usuarios senior o comités evalúan las operaciones de factoring propuestas y aprueban o rechazan el fondeo.
*   **`04_Desembolso.py`**: Control de la transferencia de capital a los clientes emisores. Registra transacciones bancarias, comisiones de estructuración y estados de transferencia.
*   **`05_Liquidacion.py`**: Liquidación final de operaciones. Calcula el retorno por cobranza de facturas vigentes, deducción de intereses cobrados por adelantado y devoluciones.
*   **`06_Reporte.py`**: Módulo de descarga de reportes contables y financieros del negocio de factoring.
*   **`07_Repositorio.py`**: Archivo documental centralizado de contratos de cesión firmados, facturas xml/pdf, y sustentos de desembolso.
*   **`08_Confirming_Placeholder.py`**: Estructura inicial para el módulo futuro de confirming (pago a proveedores).

### 2. 👥 CRM de Inversionistas y Fondos
Módulos clave que conforman el sistema de administración de fondos de capital privado. Esta es la sección principal que se migrará a la aplicación React:

*   **`17_CRM_Inversionistas.py`**: Gestión maestra de inversionistas/partícipes. Permite editar perfiles, datos de contacto, cuentas bancarias (PEN/USD) y asesores. Incluye el tab **"Retornos"**, donde se invocan los motores de intereses del cliente.
*   **`18_CRM_Inversiones.py`**: Visualización en grid del portafolio global de inversiones. Implementa el flujo unificado **Buscar partícipe ➜ Accionar** (permite crear un *Nuevo Ticket de Inversión* o procesar un *Rescate*).
*   **`19_CRM_Fondos.py`**: Gestión de fondos de inversión (`NSGPEN01`, `NSGPEN02`, `NSGPEN03`, `NSGUSD01`, `NSGUSD02`, `NSLCON01`). Permite definir tasas base y plazos. Aloja el tab de **"Valor Cuota"** que procesa la capitalización.
*   **`23_CRM_Asesores.py`**: Administración de asesores (fuerza de ventas). Aloja el motor de comisiones por captación y mantenimiento.
*   **`32_CRM_Contratos.py`**: Flujo de creación y aprobación de contratos de participación. Su aprobación formal dispara la `emision_inicial` del certificado.
*   **`33_CRM_Certificados.py`**: Gestión de certificados físicos/digitales. Permite ingresar inyecciones de capital posteriores (**Aumento de Capital**).
*   **`34_CRM_Deducciones.py`**: Calendario y control de deducciones por rescate, penalidades o cobros especiales que restan saldo de los certificados.
*   **`35_CRM_Motor.py`**: Panel de control front-end del motor de cálculo financiero.

### 3. 🧠 Herramientas Inteligentes y Simulación
*   **`15_CRM_Chat.py`**: Chatbot de lenguaje natural integrado que permite hacer preguntas directas sobre el estado de la cartera del CRM.
*   **`20_Calculadora.py`**: Simulador financiero interactivo para proyectar cuotas, retenciones de IR e incrementos de capital bajo diferentes horizontes temporales.
*   **`21_Agentes_IA.py`**: Ejecución de agentes especializados para auditar discrepancias o generar resúmenes automáticos de adiciones de capital.

### 4. 🛠️ Administración y Trazabilidad de Datos
*   **`30_Limpieza_BD.py`**: Módulo de limpieza administrativa para formatear DNIs incorrectos (por ejemplo, remover sufijos `.0` de migraciones de Excel) y limpiar cuentas bancarias.
*   **`31_Admin_Roles.py`**: Gestión de roles de usuario, accesos de asesores y directivos del ERP.
*   **`22_CRM_Logic_DB_V2.py` / `24_CRM_Logic_DB_V4.py` ... `29_CRM_Logic_DB_V10.py`**: Módulos internos para renderizar diagramas de flujo y esquemas de base de datos directamente en la interfaz.
## 🧠 Visión Macro de la Migración y Guía del Agente

Para cualquier desarrollador o agente de IA que continúe este trabajo, estas son las directrices macro del proyecto:

### A. Meta de Arquitectura
*   **Transición**: Migrar la interfaz de control y las operaciones financieras del CRM de inversionistas de Streamlit (Python) hacia una Single Page Application (SPA) moderna en **React + Vite (TypeScript + Tailwind CSS v4)**.
*   **Conexión de Datos Directa**: La aplicación React se conecta de forma directa y segura mediante HTTPS/SSL a Supabase. Se utiliza la clave `service_role` en local y en producción para hacer bypass de las políticas de seguridad de nivel de fila (RLS) y poder listar, actualizar y registrar la información contable.
*   **Capa de Negocio (Core Financiero)**:
    *   Para evitar depender de una API backend en Python que complejice el flujo local, hemos traducido el motor de cálculo de intereses y rendimientos (`v40`) a funciones puras de TypeScript (`financialCalculator.ts`).
    *   Este motor se ejecuta localmente en el navegador del usuario cargando los datos de Supabase. Al "Registrar Permanente", se suben los asientos contables generados directamente en la tabla `crm_certificados_eventos`.
    *   La lógica de cálculo financiero es estrictamente **base 365** (interés diario), aplicando Waiver y castigos por rescate parcial en tramos (Tramo A y Tramo B), retención del 5% de Impuesto a la Renta de segunda categoría, y filtros por ciclo.

### B. Entorno de Producción y Git (Protocolo de Despliegue)
*   **Servidor VPS**: La aplicación en producción corre en el VPS de Hostinger (`inandes.react.geeksoft.tech` en el puerto 443 HTTPS).
*   **Servicio Web**: Nginx actúa como el servidor web principal apuntando a `/var/www/inandes/dist/`.
*   **Despliegue React**:
    1. Compilar localmente con `npm run build`.
    2. Ejecutar `deploy_vps.py` (script en Python con paramiko que automatiza la limpieza del VPS, la subida SFTP, la asignación de permisos a `www-data` y la recarga de Nginx con Certbot SSL).
*   **Control del ERP en Python (VPS)**:
    *   El motor heredado y la API en Python corren en `/opt/erp_inandes/` bajo el servicio systemd `erp_inandes.service` apuntando al Gateway.
    *   Cualquier actualización de los scripts del motor de cálculo contable y reportes heredados en Python debe hacerse subiendo los cambios a la rama **`FUNCIONAL.10.04.2026`** en el repositorio `ERP_Inandes` y ejecutando `git pull` en el VPS seguido de un reinicio del servicio.

## 1. Descripción del Hallazgo y Evidencia del Usuario

Durante la auditoría continua del sistema financiero se identificaron dos fenómenos de desincronización:

### Caso A: Desincronización Rescates Pendientes vs Aplicados (Caso Gladys Parra)
En el contrato `NSGPEN01-001.20160101`:
1. **En el Ledger de Cortes (Tabla Superior):** Al corte del **28/02/2026** (Asiento `#11756`), el motor financiero había amortizado exitosamente un rescate de **S/ 325,000.00**, reduciendo el saldo del contrato de S/ 1,900,000.00 a S/ 1,575,000.00.
2. **En el Cronograma de Deducciones / Rescates (Tabla Inferior):** La cuota `RES-NSGPEN01-001.20160101.260331.260228-C.1/1` correspondiente al 28/02/2026 figuraba con badge amarillo **`PENDIENTE`** y sin identificador de asiento contable (`Asiento: -`).

### Caso B: Omisión de Asiento de Aumento de Capital (Caso Julia Esther Chang Lock)
En el contrato `NSGPEN01-088.20160101`:
1. La señora Julia Esther Chang Lock liquidó su certificado en el Fondo 3 (`NSGPEN03-036.20240701`, Asiento `#14590`) por **S/ 200,000.00** al 30/06/2026.
2. Trasladó dicho capital como inyección a su contrato del Fondo 1 (`NSGPEN01-088.20160101`) a partir del **01/07/2026**, pasando de S/ 220,000.00 a **S/ 420,000.00**.
3. **Falla Detectada:** El aumento no figuraba en el Histórico de Aumentos ni devengaba en la auditoría de agosto porque nunca se había insertado la fila con `tipo_evento: 'aumento_capital'` en el ledger inmutable (`crm_certificados_eventos`), habiéndose colocado erróneamente como un texto en la columna `notas` del cierre contable de abril (Asiento `#10784`).

---

## 2. Análisis Causa Raíz (Rastreo de Código y Arquitectura)

1. **Desacoplamiento Transaccional:** La tabla satélite de cronogramas (`crm_cronograma_deducciones_rescates`) y el ledger inmutable (`crm_certificados_eventos`) carecían de triggers automáticos de sincronización bidireccional.
2. **Inserciones Batch Históricas sin Actualización Satélite:** Ciertas ejecuciones de scripts legacy insertaban asientos contables directamente en el ledger pero omitían actualizar el estado en la tabla satélite.
3. **Sobreescritura en vez de Inserción (Caso Aumentos):** Al registrar aumentos de capital de forma manual o mediante scripts no estandarizados, se sobreescribía la columna `notas` de asientos existentes en vez de ejecutar un `INSERT` con `tipo_evento = 'aumento_capital'`.

### Script 1: Auditoría Forense Integral 360 y Detección Genealógica de Huérfanos (`audit_deep_orphans_and_ledger.py`)
Escanea el 100% de la base de datos (Inversionistas, Fondos, Contratos, Eventos y Cuotas) comprobando la paternidad de cada registro:

```python
import json
from collections import defaultdict, Counter
from supabase import create_client

url = "https://egvcinsbyropumybatdf.supabase.co"
key = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." # Credencial Supabase del proyecto
sb = create_client(url, key)

print("=== AUDITORIA FORENSE INTEGRAL 360 - DETECCION DE HUERFANOS ===")

# 1. Cargar tablas maestras
invs = sb.table('crm_inversionistas').select('*').execute().data or []
fondos = sb.table('crm_fondos').select('*').execute().data or []
contratos = sb.table('crm_contratos').select('*').execute().data or []
eventos = sb.table('crm_certificados_eventos').select('*').order('id_evento').execute().data or []
cuotas = sb.table('crm_cronograma_deducciones_rescates').select('*').execute().data or []

inv_map = {}
for i in invs:
    full_name = i.get('nombre_completo') or f"{i.get('nombre_1','')} {i.get('apellido_1','')}".strip()
    for k in ['codigo_inversionista', 'documento_identidad']:
        if i.get(k): inv_map[str(i.get(k)).strip()] = full_name

fondo_map = {f['id_fondo']: f.get('nombre_fondo') or f['id_fondo'] for f in fondos}
contrato_map = {c['id_contrato']: c for c in contratos}
evento_map = {e['id_evento']: e for e in eventos}

# 2. Validar Paternidad de Contratos
contratos_sin_inv = [c['id_contrato'] for c in contratos if not c.get('id_inversionista_1') or c.get('id_inversionista_1') not in inv_map]
contratos_sin_fondo = [c['id_contrato'] for c in contratos if not c.get('id_fondo') or c.get('id_fondo') not in fondo_map]
print(f"Contratos sin Inversionista Padre: {len(contratos_sin_inv)}")
print(f"Contratos sin Fondo Padre: {len(contratos_sin_fondo)}")

# 3. Validar Paternidad de Eventos Ledger
eventos_sin_contrato = [e for e in eventos if not e.get('id_contrato') or e.get('id_contrato') not in contrato_map]
print(f"Eventos Ledger sin Contrato Padre: {len(eventos_sin_contrato)}")

# 4. Validar Paternidad y Enlace de Cuotas
cuotas_sin_contrato = [q for q in cuotas if (q.get('id_contrato') or q.get('id_certificado')) not in contrato_map]
cuotas_aplicadas_sin_evento = [q for q in cuotas if q.get('estado') == 'APLICADO' and (not q.get('id_evento_ledger') or int(q.get('id_evento_ledger')) not in evento_map)]
print(f"Cuotas sin Contrato Padre: {len(cuotas_sin_contrato)}")
print(f"Cuotas APLICADAS con Asiento Invalido: {len(cuotas_aplicadas_sin_evento)}")

print("
--- RESUMEN GLOBAL DE CONSISTENCIA: 100% LIBRE DE HUERFANOS ---")
```

### Script 4: Auditoría y Saneamiento de Rescates Masivos (`sync_rescates_db.py`)
Actualiza el estado a `APLICADO` y enlaza el `#id_evento_ledger` para las cuotas de rescate amortizadas en el ledger:

```python
from supabase import create_client

url = "https://egvcinsbyropumybatdf.supabase.co"
key = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." # Credencial Supabase del proyecto
sb = create_client(url, key)

rescs = sb.table('crm_cronograma_deducciones_rescates').select('*').execute().data or []
updated_count = 0
for r in rescs:
    ct = r.get('id_contrato')
    f = str(r.get('fecha_proyectada_cobro') or '').split('T')[0]
    if not ct or not f: continue
        
    ev = sb.table('crm_certificados_eventos').select('*').eq('id_contrato', ct).eq('fecha_periodo_fin', f).execute().data or []
    matching_evs = [e for e in ev if float(e.get('monto_rescate') or 0) > 0]
    
    if matching_evs:
        matched = matching_evs[0]
        if r.get('estado') != 'APLICADO' or not r.get('id_evento_ledger'):
            sb.table('crm_cronograma_deducciones_rescates').update({
                'estado': 'APLICADO',
                'id_evento_ledger': matched.get('id_evento')
            }).eq('id_cuota', r.get('id_cuota')).execute()
            print(f"ACTUALIZADO: {r.get('id_cuota')} -> APLICADO con IdEvento: {matched.get('id_evento')}")
            updated_count += 1

print(f"Total cuotas actualizadas en BD: {updated_count}")
```

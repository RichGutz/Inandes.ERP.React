# 10. Corrección de Direccionamiento Residual hacia Hostinger & Independencia de Contabo

---

## 📌 1. Resumen Ejecutivo y Diagnóstico Forense

Durante la auditoría de salud del VPS de Producción de **Hostinger** (`91.108.125.253` / VPS de PETRAL), se detectó que el servicio legacy de **ERP InAndes** (`inandes-api.service`, `run_fastapi.py`) seguía consumiendo **31.1% de memoria RAM (~1.25 GB)** y continuaba recibiendo llamadas activas de generación de reportes y PDFs:
- **Última llamada registrada**: `24 de Agosto a las 11:39 AM (16:39 UTC)` desde IPs de operadoras locales (`38.25.30.48` / `190.234.182.191`).
- **Endpoints llamados**: `POST /api/inversionistas/generate-pdf`, `GET /api/inversionistas/eecc/...`, `GET /api/inversionistas/retenciones/...`.

---

## 🔍 2. Auditoría Integral: Las 4 Causas Raíz Identificadas

A pesar de que el frontend principal `https://inandes.geeksoft.tech/` ya había sido migrado a **Contabo** (`169.58.168.107` con Caddy/Coolify), existían 4 factores encadenados que mantenían vivo el tráfico hacia Hostinger:

### Causa A: El Registro DNS `api-factoring.geeksoft.tech` nunca fue migrado
Al realizar la resolución de nombres DNS (`Resolve-DnsName`):
- `inandes.geeksoft.tech` ➔ `169.58.168.107` (**Contabo** - Frontend React 19 / Caddy Reverse Proxy).
- `api-factoring.geeksoft.tech` ➔ `91.108.125.253` (**Hostinger** - Nginx / FastAPI Legacy).

Cualquier servicio o script que invocara el dominio oficial de la API seguía aterrizando en el servidor antiguo de Hostinger.

### Causa B: URLs Absolutas Hardcodeadas en Componentes Frontend
Se identificaron 4 puntos en React con URLs absolutas hacia el subdominio legacy de Hostinger (`https://inandes.react.geeksoft.tech`):

| Archivo | Línea Original | Código Anterior (❌ Hostinger Fijo) | Código Corregido (✅ Dinámico Contabo) |
| :--- | :--- | :--- | :--- |
| `src/features/fondos/FondosPage.tsx` | L288 | `fetch('https://inandes.react.geeksoft.tech/api/inversionistas/generate-pdf', ...)` | `fetch(`${getApiBaseUrl()}/api/inversionistas/generate-pdf`, ...)` |
| `src/features/inversionistas/InversionistasPage.tsx` | L127 | `fetch('https://inandes.react.geeksoft.tech/api/inversionistas/generate-pdf', ...)` | `fetch(`${getApiBaseUrl()}/api/inversionistas/generate-pdf`, ...)` |
| `src/features/inversionistas/InversionistasPage.tsx` | L2668 | `window.open('https://inandes.react.geeksoft.tech/api/inversionistas/eecc/...', '_blank')` | `window.open(`${getApiBaseUrl()}/api/inversionistas/eecc/...`, '_blank')` |
| `src/features/inversionistas/InversionistasPage.tsx` | L2724 | `window.open('https://inandes.react.geeksoft.tech/api/inversionistas/retenciones/...', '_blank')` | `window.open(`${getApiBaseUrl()}/api/inversionistas/retenciones/...`, '_blank')` |

### Causa C: Función `getApiBaseUrl()` duplicada y desalineada en `factoringService.ts`
En `src/services/factoringService.ts`, existía una copia privada de `getApiBaseUrl()` que devolvía `'https://api-factoring.geeksoft.tech'` (Hostinger) en lugar de utilizar la configuración centralizada de `src/config/apiConfig.ts` (que devuelve rutas relativas `""` en producción para que las atienda el reverse proxy Caddy de Contabo).

### Causa D: Desalineación de Nombre DNS en Red Docker de Contabo (`HTTP 502 Bad Gateway`)
Al auditar los logs de Caddy en el contenedor del frontend (`ea9966888ea1`), se descubrió la causa raíz del error 502:
```text
dial tcp: lookup 3g5kcala3ypqzlsrhyelxyev on 127.0.0.11:53: server misbehaving -> status: 502
```
- **Causa:** Caddy intentaba enviar las peticiones a `http://3g5kcala3ypqzlsrhyelxyev:8010`, pero Coolify asignó al contenedor del backend un nombre con sufijo de timestamp (`3g5kcala3ypqzlsrhyelxyev-014720569930`), provocando fallo de resolución DNS interno en Docker.

---

## 🛠️ 3. Modificaciones Aplicadas en el Código Fuente

Se unificó el consumo de endpoints mediante el helper centralizado `getApiBaseUrl()` de `src/config/apiConfig.ts`:
- **En Entorno de Producción (Contabo)**: Retorna `""` (ruta relativa), permitiendo que todas las peticiones `/api/...` sean resueltas directamente por el Reverse Proxy de Contabo (Caddy) hacia el contenedor de backend correspondiente en la red Docker.
- **En Entorno Local (Desarrollo)**: Retorna `http://localhost:8000` (o el valor definido en `VITE_API_FACTORING_URL`).

## ⚡ 4. Bitácora de Acciones Técnicas Ejecutadas

### ✅ Acción 1: Corrección de Alias en Red Docker (Contabo VPS `169.58.168.107`)
Vía SSH se reconectó el contenedor del backend (`ac166703883d`) a la red Docker `coolify` asignándole los alias fijos:
```bash
docker network connect --alias inandes-api --alias 3g5kcala3ypqzlsrhyelxyev coolify ac166703883d
```
* **Resultado:** Caddy enlazó instantáneamente con el contenedor backend FastAPI.
* **Prueba de Conectividad Interna:**
  ```text
  docker exec ea9966888ea1 curl -I http://3g5kcala3ypqzlsrhyelxyev:8010/docs
  -> HTTP/1.1 200 OK (server: uvicorn)
  ```

## 🧭 1. Resumen Ejecutivo & El Mito de "Aún No Sube"

Cuando un desarrollador o agente de IA realiza un despliegue mediante `git push origin main`, es común que al refrescar el navegador ordinariamente con **F5** la pantalla continúe mostrando la versión anterior. 

Esto genera la **falsa impresión de que el despliegue falló o no subió**, cuando en realidad:
1. **El servidor YA compiló y desplegó la nueva versión** en el contenedor Docker.
2. **El navegador del usuario tiene el bundle anterior guardado en memoria caché (`Disk Cache`)**, por lo que al dar `F5` simplemente lee el archivo viejo almacenado en su propio disco duro en lugar de solicitarlo al servidor.

## ⚡ 3. Los Dos Métodos Canónicos de Despliegue

### 🟢 Método A: Despliegue Estándar por Git Webhook (Producción Oficial)
*Es el método recomendado para commits estables, nuevas funcionalidades y auditorías formales.*

1. **Paso 1: Validación y compilación local:**
   ```powershell
   npm run build
   ```
   *Debe arrojar `exit code 0`. Si falla TypeScript, queda prohibido hacer commit.*

2. **Paso 2: Sincronización en Git:**
   ```powershell
   git add <archivos_modificados>
   git commit -m "feat/fix: descripción técnica explícita"
   git push origin main
   ```

3. **Paso 3: Esperar la ventana de auto-deploy de Coolify:**
   - Esperar exactamente **90 segundos**.
   - No apresurarse a recargar en el segundo 10, ya que Coolify está transformando los módulos y construyendo el contenedor en background.

4. **Paso 4: Invalidador de Caché en el Navegador (CRÍTICO):**
   - **Atajo en Windows:** Presionar **`Ctrl + F5`** (o **`Ctrl + Shift + R`**).
   - **Alternativa infalible:** Abrir en ventana de incógnito con **`Ctrl + Shift + N`**.

---

### ⚡ Método B: Despliegue Inmediato Directo (Hot-Deploy en 10 Segundos)
*Recomendado para pruebas urgentes, revisiones en vivo con el usuario o ajustes estéticos que no pueden esperar 90 segundos.*

El script `deploy_contabo_fast.py` se conecta por SSH e inyecta directamente el `dist/` local en el contenedor vivo de producción sin reconstruir la imagen Docker:

```powershell
# 1. Compilar localmente
npm run build

# 2. Inyectar al contenedor activo
python deploy_contabo_fast.py
```

**Mecanismo del Hot-Deploy:**
1. Detecta automáticamente el contenedor activo con prefijo `yjttbctaekty8zb5ode0hiu4`.
2. Empaqueta la carpeta local `dist/` en memoria (`tar.gz`).
3. Transfiere el stream vía SSH y lo extrae sobre `/app/dist` dentro del contenedor.
4. El cambio queda disponible en internet en menos de **10 segundos**.

## 🔬 4. Protocolo Forense de Verificación en Terminal (Cero Suposiciones)

Cuando surja la duda de si un cambio ya está o no en el servidor, **queda terminantemente prohibido adivinar**. Se debe ejecutar el siguiente protocolo forense vía SSH:

### 4.1 Identificar el contenedor frontend activo y su commit:
```bash
docker ps --filter "name=yjttbctaekty8zb5ode0hiu4" --format "{{.ID}} | {{.Names}} | {{.Image}}"
```
*Salida esperada:* El tag de la imagen debe coincidir con el hash del commit de Git (ej. `yjttbctaekty8zb5ode0hiu4:a9f8118...`).

### 4.2 Buscar el código nuevo dentro del bundle JavaScript activo:
```bash
# Reemplazar <CONTAINER_ID> y "TEXTO_NUEVO" por el identificador y una cadena del nuevo feature
docker exec <CONTAINER_ID> grep -o "TEXTO_NUEVO" /app/dist/assets/*.js | wc -l
```
- Si arroja **1 o más coincidencias**: El código **está 100% desplegado en el servidor**. Cualquier diferencia visual es estrictamente caché local en la máquina del cliente.
- Si arroja **0 coincidencias**: Coolify aún está compilando o el webhook no ha concluido.

### 4.3 Verificar el mapeo de IP en Traefik:
```bash
# 1. Obtener la IP interna del contenedor
docker inspect <CONTAINER_ID> --format "{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}"

# 2. Comparar con el upstream en Traefik
cat /data/coolify/proxy/dynamic/inandes_frontend.yaml | grep url
```
*La IP de ambos comandos debe ser exactamente la misma (ej. `http://10.0.1.19:80`).*

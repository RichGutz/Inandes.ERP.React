## 1. Visión General & Filosofía de Seguridad

Cuando se distribuye un pitch comercial o técnico con información altamente sensible (modelos predictivos WoE/XGBoost, algoritmos de score, estructuras tarifarias por microservicios y arquitectura propietaria), el uso de PDFs tradicionales o enlaces estáticos de PowerPoint representa un riesgo crítico de fuga de información.

Para resolver esto, diseñamos una **Bóveda Web Interactiva Monolítica Auto-Contenida** que implementa un modelo de **Defensa en Profundidad en 6 Capas**:

```
+-------------------------------------------------------------------------+
|                  CAPA 0: BLOQUEO DE DISPOSITIVOS MÓVILES                |
|    (Detección User-Agent + Viewport < 960px -> Overlay de Bloqueo)      |
+-------------------------------------------------------------------------+
                                    │
                                    ▼
+-------------------------------------------------------------------------+

|   (Validación contra Padrón Institucional -> Cero Correos Públicos)     |

                                    │
                                    ▼
+-------------------------------------------------------------------------+

+-------------------------------------------------------------------------+
                                    │
                                    ▼

                                    │

+-------------------------------------------------------------------------+
```

## 2. Capa 0: Bloqueo de Dispositivos Móviles (Smartphones y Tablets)

### Justificación
Las pantallas de smartphones no permiten una adecuada legibilidad de diagramas de arquitectura complejos y facilitan la captura descontrolada de información. La presentación se bloquea automáticamente en cualquier resolución menor a 960px o User-Agent móvil.

```html
        <h2>Presentación disponible solo para dispositivos de escritorio</h2>

        <div class="mobile-block-instruction">

```

### Script de Detección en Tiempo Real
```javascript
function checkMobileDevice() {
    const isMobileUA = /Android|webOS|iPhone|iPad|iPod|BlackBerry|IEMobile|Opera Mini|Mobile|mobile/i.test(navigator.userAgent);
    const isNarrow = window.innerWidth < 960 || (window.screen && window.screen.width < 960);

    const mobileEl = document.getElementById('mobile-block-overlay');
    const authEl = document.getElementById('auth-overlay');
    const deckEl = document.getElementById('deck');
    const progressEl = document.getElementById('progress');

    if (isMobileUA || isNarrow) {
        if (mobileEl) mobileEl.style.display = 'flex';
        if (authEl) authEl.style.display = 'none';
        if (deckEl) deckEl.style.display = 'none';
        if (progressEl) progressEl.style.display = 'none';
        return true;
    } else {
        if (mobileEl) mobileEl.style.display = 'none';
        if (deckEl && (!authEl || authEl.classList.contains('hidden'))) {
            deckEl.style.display = 'block';
        }
        if (progressEl) progressEl.style.display = 'block';
        return false;
    }
}

window.addEventListener('resize', checkMobileDevice);
window.addEventListener('orientationchange', checkMobileDevice);
```

## 4. Capa 2: Despacho Transaccional Multi-Ruta & Auditoría BCC

### Justificación
Para garantizar que el código OTP llegue en menos de 3 segundos a cualquier corporativo y asegurar tolerancia a fallos, se implementa una cascada de 3 rutas de envío:

1. **Ruta Primaria:** Endpoint Backend Proxy Oficial HTTPS (`https://apefac.geeksoft.tech/api/send-otp`).
2. **Ruta Secundaria (Fallback Directo):** Conexión directa vía Fetch API a los servidores de `https://api.resend.com/emails`.
3. **Ruta Terciaria (Local):** Proxy inverso relativo (`/api/send-otp`).

### Auditoría Ciega (BCC Encubierto)
Cada solicitud de código dispara simultáneamente una copia oculta a los correos de los auditores del proyecto (`rgutil@gmail.com` y `rich@kaizencapital.pe`). Esto permite supervisar en tiempo real quién está intentando acceder al pitch sin que el destinatario lo perciba.

```javascript
// Generación criptográfica del OTP de 6 dígitos
pendingGeneratedOtp = Math.floor(100000 + Math.random() * 900000).toString();

const emailPayload = {
    from: 'APEFAC Risk Core <apefac@geeksoft.tech>',
    to: [cleanEmail],
    bcc: ['rgutil@gmail.com', 'rich@kaizencapital.pe'],
    subject: `Código de Acceso Presentación APEFAC: ${pendingGeneratedOtp}`,
    html: corporateHtml
};

let dispatched = false;

// 1. Intento A: Endpoint Proxy Oficial HTTPS
try {
    const resA = await fetch('https://apefac.geeksoft.tech/api/send-otp', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(emailPayload)
    });
    if (resA.ok) dispatched = true;
} catch (errA) {}

// 2. Intento B: Directo a Resend API
if (!dispatched) {
    try {
        const resB = await fetch('https://api.resend.com/emails', {
            method: 'POST',
            headers: {
                'Authorization': 'Bearer ' + RESEND_API_KEY,
                'Content-Type': 'application/json'
            },
            body: JSON.stringify(emailPayload)
        });
        if (resB.ok) dispatched = true;
    } catch (errB) {}
}
```

## 5. Capa 3: Sesión Volátil en Memoria (Opción 3: Cero Persistencia)

### Justificación
Si el usuario guarda el token de autorización en `localStorage` o `cookies`, cualquier persona que utilice esa computadora posteriormente podrá ver la presentación sin ingresar credenciales. Con la **Opción 3**, cada vez que se recarga la página (`F5`) o se abre una nueva pestaña, se destruye cualquier sesión y se exige un nuevo 2FA.

```javascript
function checkDeviceAuthorization() {
    // Purga forzada de cualquier almacenamiento local persistente
    try {
        localStorage.removeItem('apefac_presentation_device_token');
        localStorage.removeItem('apefac_presentation_auth_email');
        sessionStorage.clear();
    } catch(e) {}

    authOverlayEl.classList.remove('hidden');
    document.getElementById('auth-step-1').style.display = 'block';
    document.getElementById('auth-step-2').style.display = 'none';
}
```

## 6. Capa 4: Huella Digital de Hardware & Marca de Agua Forense

### Generador de Device Fingerprint
Calcula un hash determinístico derivado de las características físicas del equipo (GPU, CPU Cores, Resolución de Pantalla y User-Agent):

```javascript
function getDeviceFingerprint(email) {
    const raw = email + '|' + (navigator.userAgent || '') + '|' + (screen.width || 0) + 'x' + (screen.height || 0) + '|' + (navigator.hardwareConcurrency || 4);
    let hash = 0;
    for (let i = 0; i < raw.length; i++) {
        hash = ((hash << 5) - hash) + raw.charCodeAt(i);
        hash |= 0;
    }
    return 'DEV-' + Math.abs(hash).toString(16).toUpperCase();
}
```

### Inyección de la Matriz Forense Anti-Fotografía
Genera una capa invisible sobrepuesta (`pointer-events: none; z-index: 99998; opacity: 0.04; transform: rotate(-25deg);`) con 40 marcas de agua distribuidas en toda la pantalla. Si el usuario intenta tomar una fotografía con su smartphone a la pantalla, la foto registrará de forma indeleble su correo, ID de máquina y timestamp exacto:


### Event Listeners de Seguridad Activa
```javascript
// Desactivar menú contextual (Click Derecho) y selección de texto
document.addEventListener('contextmenu', e => e.preventDefault());
document.addEventListener('selectstart', e => e.preventDefault());
document.addEventListener('dragstart', e => e.preventDefault());

// Detección de pérdida de foco (Ventana desenfocada o Snipping Tool activo)
window.addEventListener('blur', () => {
    document.body.classList.add('screen-blurred');
});

window.addEventListener('focus', () => {
    document.body.classList.remove('screen-blurred');
});

document.addEventListener('visibilitychange', () => {
    if (document.hidden) {
        document.body.classList.add('screen-blurred');
    } else {
        document.body.classList.remove('screen-blurred');
    }
});

// Interceptar tecla ImprPant (PrintScreen) y vaciar el Clipboard del SO
window.addEventListener('keyup', (e) => {
    if (e.key === 'PrintScreen' || e.keyCode === 44) {
        if (navigator.clipboard && navigator.clipboard.writeText) {
            navigator.clipboard.writeText('');
        }
        triggerScreenshotShield();
    }
});

// Bloquear atajos de desarrollador (F12, Ctrl+Shift+I) y guardado (Ctrl+S, Ctrl+P, Ctrl+U)
window.addEventListener('keydown', (e) => {
    if ((e.ctrlKey || e.metaKey) && ['s', 'p', 'u', 'c', 'a'].includes(e.key.toLowerCase())) {
        e.preventDefault();
        return false;
    }
    if (e.key === 'F12' || ((e.ctrlKey || e.metaKey) && e.shiftKey && ['i', 'j', 'c'].includes(e.key.toLowerCase()))) {
        e.preventDefault();
        return false;
    }
});
```

## 8. Homologación Visual Cromática (Modal vs Plantilla de Correo)

Para evitar el problema común donde el logo corporativo JPEG tiene un fondo off-white (`#f4f6f5`) que contrasta de forma antiestética con una tarjeta blanca (`#ffffff`):

1. **Contenedor Ribbon (`.auth-header-ribbon`):** Se aplica exactamente `background-color: #f4f6f5;`.
2. **Barra Superior Gradiente:** `height: 6px; background: linear-gradient(90deg, #0284c7 0%, #0369a1 100%);`.
3. **Cuerpo del Modal (`.auth-body`):** Se mantiene en `#ffffff` con una línea divisoria limpia `border-bottom: 1px solid #e2e8f0;`.

De esta forma, la experiencia visual del modal web es **idéntica pixel por pixel al correo que el usuario recibe en su bandeja de entrada**.

## 9. Procedimiento de Automatización & Despliegue en VPS

### Script de Control de Calidad Previo (QC en Terminal)
Antes de cualquier despliegue, se ejecuta un script de prueba que simula 33 casos de prueba:
- Aceptación de colaboradores con dominios corporativos (`usuario@chita.pe` -> PASS).
- Rechazo inmediato de correos públicos (`hacker@gmail.com` -> REJECT).
- Verificación de integridad de funciones JS (`handleSendAuthCode`, `handleVerifyOtp`, `updateDeck`).

### Script de Despliegue en Caliente vía Paramiko SSH / Docker
```python
import paramiko
import json
import os

with open(r"C:\Users\rguti\.gemini\antigravity-ide\scratch\contabo_credentials.json", "r") as f:
    creds = json.load(f)

vps_info = creds.get("contabo_vps", {})
host = vps_info.get("ip", "169.58.168.107")
user = vps_info.get("user", "root")
password = vps_info.get("pass")

ssh = paramiko.SSHClient()
ssh.set_missing_host_key_policy(paramiko.AutoAddPolicy())
ssh.connect(host, username=user, password=password, timeout=10)

sftp = ssh.open_sftp()
local_pres = r"C:\Users\rguti\APEFAC\docs\presentations\presentation.html"
local_v22 = r"C:\Users\rguti\APEFAC\docs\presentations\presentation_V22.html"

# Subida a rutas temporales del host
sftp.put(local_pres, "/tmp/presentation.html")
sftp.put(local_v22, "/tmp/presentation_V22.html")

# Inyección directa dentro del contenedor Docker de Nginx sin reiniciar servicios
stdin, stdout, stderr = ssh.exec_command("docker ps --filter name=apefac_risk_core_frontend -q")
cid = stdout.read().decode().strip()

if cid:
    ssh.exec_command(f"docker cp /tmp/presentation.html {cid}:/usr/share/nginx/html/presentation.html")
    ssh.exec_command(f"docker cp /tmp/presentation_V22.html {cid}:/usr/share/nginx/html/presentation_V22.html")

sftp.close()
ssh.close()
print("Despliegue en caliente completado con éxito.")
```

## 10. Conclusión & Guía Rápida de Replicación

1. Clonar la plantilla base `presentation_V22.html`.
2. Actualizar el array `ALLOWED_DOMAINS` y el objeto `DOMAIN_TO_COMPANY` con los dominios del cliente.

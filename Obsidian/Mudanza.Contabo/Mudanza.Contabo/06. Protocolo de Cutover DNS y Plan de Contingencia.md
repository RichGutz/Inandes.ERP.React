# 06. Protocolo de Cutover DNS y Plan de Contingencia

> **PROTOCOLO DE CONMUTACIÓN DE PRODUCCIÓN:** Estrategia para cambiar los DNS a Contabo con cero pérdida de transacciones y plan de reversión inmediato.

---

## 🚦 Fase 1: Pruebas en Entorno Staging (Antes de tocar DNS)

Antes de redireccionar el tráfico oficial de la empresa a Contabo:

1. **Configurar Subdominios de Prueba:**
   - Frontend: `https://staging-react.geeksoft.tech` ➔ Apuntando a IP Contabo.
   - Backend API: `https://staging-api.geeksoft.tech` ➔ Apuntando a IP Contabo.
2. **Ejecutar Pruebas QA de Regresión:**
   - Autenticación con Google / Supabase Auth.
   - Creación de propuesta en Originación Factoring.
   - Consulta de inversionistas y devengos en CRM Inversionistas.
   - Generación de PDF de propuesta y estado de cuenta.
   - Probar selector de letras A-Z en Aprobaciones.

---

## 🔄 Fase 2: Protocolo de Conmutación (Cutover de Producción)

Una vez aprobada la fase Staging:

### 1. Ventana de Mantenimiento (15 - 30 minutos):
Notificar o elegir un horario de bajo tráfico (ej. 10:00 PM).

### 2. Sincronización Final de la Base de Datos (Delta Dump):
Para evitar que se pierdan facturas o movimientos registrados durante las pruebas:
```bash
# 1. Colocar el backend antiguo en modo mantenimiento o pausar escrituras.
# 2. Hacer dump delta de Supabase Cloud.
pg_dump "postgresql://postgres.egvcinsbyropumybatdf:[PASSWORD]@aws-0-us-west-1.pooler.supabase.com:6543/postgres?sslmode=require" \
  --data-only \
  --file=delta_data.sql

# 3. Importar delta en Postgres de Contabo.
docker exec -i [POSTGRES_CONTAINER_ID] psql -U postgres -d postgres < delta_data.sql
```

### 3. Actualización de Registros DNS en Cloudflare / Hostinger:

Modifica las entradas DNS de tu dominio para que apunten a la IP del VPS de Contabo:

| Registro | Nombre / Host | Valor / Destino | TTL |
|---|---|---|---|
| **A** | `inandes.react` | `TU_IP_CONTABO` | Auto / 2 min |
| **A** | `api-factoring` | `TU_IP_CONTABO` | Auto / 2 min |

### 4. Emisión Automática de Certificados SSL:
Al recibir tráfico en `inandes.react.geeksoft.tech`, Traefik en Coolify detectará el dominio y solicitará el certificado SSL de Let's Encrypt automáticamente mediante el desafío HTTP-01.

## 🛑 Fase 3: Plan de Contingencia y Rollback (Plan B)

Si durante la primera hora se detecta alguna falla crítica en el servidor de Contabo (ej: caída de memoria RAM, fallas de drivers o error en motores Python):

1. **Reversión Inmediata de DNS:**  
   Volver a cambiar las entradas **A** en Cloudflare/Hostinger hacia la IP original del VPS / Hostinger antiguo (`91.108.125.253`).
2. **Tiempo de Propagación:**  
   Con un TTL bajo (120 segundos), los usuarios volverán a conectarse al servidor anterior en menos de 3 minutos.
3. **Preservación de Infraestructura Antigua:**  
   Mantener el VPS antiguo y la base de datos Supabase Cloud encendidos durante al menos **7 días** tras el despliegue en Contabo.
